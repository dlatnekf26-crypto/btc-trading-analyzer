# 무료 공개 웹 배포

이용자는 Python을 설치하지 않고 웹 주소로 접속합니다. **호스팅 계정에서 최초 배포를 완료해야 실제 공개 주소가 생깁니다.** Codex 환경 저장/게시만으로 인터넷 웹사이트가 배포되지는 않습니다.

## Streamlit Community Cloud

PWA를 포함한 공개 시작 파일은 **web_app.py**, 고정 운영 의존성은 Streamlit **1.65**입니다. 공식 `st.App` 라우트가 manifest·service worker·고정 아이콘/오프라인 안내를 제공합니다. 기존 Cloud 앱도 같은 시작 파일로 다시 빌드해야 설치 기능이 반영됩니다. `app.py` 직접 실행도 시세 목록·상세 분석을 제공하지만 PWA 주소는 제공하지 않습니다.

HTTPS의 루트 경로(`/`)에 배포하세요. 리버스 프록시는 `/manifest.webmanifest`, `/service-worker.js`, `/app-assets/*` 및 Streamlit WebSocket을 같은 출처로 전달해야 합니다. `server.enableStaticServing`은 계속 false이며 CORS/XSRF를 끄지 않습니다. worker는 올바른 JavaScript MIME과 `/` 범위로 제공하고, 캐시는 아이콘 2개/연결 안내 HTML만 보관합니다. 시장 API·HTML 대시보드·예측·개인 기록을 저장하지 않습니다. 오프라인 중에는 실시간 화면 대신 연결 안내를 표시하고 다시 연결하면 새 데이터를 요청합니다.

배포 후 상단 **앱으로 설치**를 누르거나 iOS Safari **공유 → 홈 화면에 추가**를 사용하세요. 브라우저 설치 지원/이미 설치 여부에 따라 메뉴가 다릅니다. 새 버전은 다음 앱 시작 시 적용하며 열린 차트를 강제로 새로고침하지 않습니다. 설치 파일과 개발 Chromium 검증은 실제 공개 배포나 물리 iPhone 검증과 구분합니다.

1. [Streamlit Community Cloud](https://share.streamlit.io/)에 본인의 GitHub 계정으로 로그인합니다. 저장소 접근 권한을 연결합니다. 비밀번호·인증 토큰을 채팅이나 소스 파일에 넣지 않습니다.
2. **Create app** / **New app**에서 다음을 입력합니다.

   | 항목 | 값 |
   |---|---|
   | Repository | `dlatnekf26-crypto/btc-trading-analyzer` |
   | Branch | `main` |
   | Main file path | `web_app.py` |
   | Python version · Advanced settings | `3.12` |

3. **Deploy**를 누릅니다. 빌드 후 서비스가 제공하는 `https://…streamlit.app` 주소를 휴대폰/PC에서 엽니다. 공유하려면 앱의 공개 접근 설정도 확인합니다.

`requirements.txt`에 런타임 라이브러리의 정확한 버전을 직접 나열합니다. 앱은 진입점 위치를 기준으로 `src/`를 읽으므로 프로젝트의 별도 editable 설치나 서버 작업 디렉터리에 의존하지 않습니다. 분석에는 거래소 API 키가 필요하지 않습니다. 자동 설치 실패 시 앱 로그에서 Python 버전과 설치 오류를 확인합니다. 저장소 파일이 GitHub의 `main`에 올라 있어야 배포할 수 있습니다.

## 이미 배포된 앱에 수정 반영하기

연결된 GitHub 브랜치의 변경 사항은 Community Cloud가 자동 반영합니다. 코드나 의존성 변경 후 빌드가 완료될 때까지 기다린 뒤 새로고침하세요. 같은 오류 화면이 계속되면 **Manage app → Reboot app**을 사용합니다. 새 앱을 만들 필요는 없습니다.

`ModuleNotFoundError`가 계속되면 Manage app의 로그에서 마지막 `No module named '…'`와 의존성 설치 오류를 확인합니다. 개발 환경과 같은 설치 상태라는 가정 없이 검증하려면 아래를 새 가상환경에서 실행합니다.

```bash
python -m pip install -r requirements.txt
python -I scripts/check_deployment.py
```

이 검사는 개발 전용 CCXT 응답 주입으로 Binance Live의 네 개 탭·다섯 시간대 차트·기간별 예측·과거 비교와 계좌 저장을 생성하지 않는 시작 경로를 확인합니다. 제품에는 Demo 선택이나 숨은 테스트 모드가 없습니다. CI에서도 개발 패키지 설치와 별개로 검증합니다.

예상 가격은 추세·모멘텀·변동성·거래량·일목을 자동 검토하고 과거 비교 오차가 줄어든 기간에 지표를 고려한 사례/가중치를 반영합니다. 그래프 아래 가격 산출 근거에서 실제 가격·지표 반영/보류와 현재 지표 상태를 확인합니다. 기존 공개 확정 봉을 재사용하며 추가 API 키·의존성·외부 도메인이 필요하지 않습니다. 자료 부족/개선 기준 미달이면 가격 보정을 보류하는 정상 동작이며 이유가 표시됩니다.

시장 개요의 공포·탐욕 지수는 서버 HTTPS `api.alternative.me/fng/?limit=30&format=json`을 사용합니다. API 키나 새 운영 패키지는 필요하지 않습니다. 일별 0~100 점수/공급자 분류·전일 변화·기준 시각과 Alternative.me 출처를 표시하며 실시간 시세로 취급하지 않습니다. 기존 맥락 서비스의 작업자 최대 4개·진행 중 요청 하나·오류/Retry-After·마지막 값 보존과 60초 캐시를 공유합니다. 1분마다 최신 원자료를 확인하고 원자료 기준 시각과 마지막 확인 시각을 구분합니다. 공급자는 일별 발표이며 틱 실시간 지수로 바꾸지 않습니다. 상세 화면 확인은 별도 10초 fragment, 목록의 작은 요약은 2초 fragment이며 같은 서버 캐시를 재사용합니다. 소스가 48시간 넘었거나 조회 실패면 마지막 값·조회 지연으로 표시하며 값을 만들지 않습니다.

앞선 해당 API 요청은 개발 프록시 **CONNECT 403 Forbidden**으로 차단됐고 기존 도메인·프리셋/설치/비밀 설정을 보존해 `api.alternative.me`를 환경 초안에 추가했습니다. **2026-10-07 실행 환경 재시작 후 실제 조회/파싱은 성공**했습니다. 19:05 UTC 확인 값은 71점·탐욕, 원자료 시각은 당일 00:00 UTC이고 최근 일별 이력 30개를 받았습니다. 과거 차단을 현재 실패로 표시하지 않습니다. 초안 저장만으로 적용을 주장한 것은 아니며 이번 성공은 실제 자료원 확인에 근거합니다. 공개 Streamlit의 네트워크/재배포는 별도 미확인이고 fixture 32점은 실제 현재값이 아닙니다.

연도별 1~12월 히트맵은 기존 Binance 확정 월봉으로 시가→종가 등락률을 계산합니다. 전체 이력 기본/최근 5년·선택 이력 월별 평균/연도 수와 모바일 상·하반기 표시를 제공합니다. UTC 실제 월 마감·잘못된/중복/미완결 봉은 제외하고 거래 시작 부분월도 평균에서 제외합니다. 내용 캐시 1시간/24개·이력 fragment·native 터치/마우스 상세로 새 iframe·소켓·차트 SDK나 상위 봉/가격 모델 재실행 없이 표시합니다. 차트 밖 스크롤과 자유 가격 조회를 유지합니다.

시장 개요의 **주요 지표 발표와 예상치**는 예측의 `ui/economic_releases.py` 캘린더 resource와 같은 작업자/30분 캐시를 공유합니다. 서버 HTTPS `nfs.faireconomy.media/ff_calendar_thisweek.json` 공개 주간 자료의 정확한 발표 시각/예상/이전값을 구분하고 최대 6건을 KST로 표시합니다. 5초 표시 fragment가 봉/예측 분석이나 코인 연결을 재실행하지 않습니다. 없는 예상치/실제 결과/다음 주 일정은 만들지 않으며 오류/2시간 초과 확인값은 보류합니다. 이 도메인의 이전 실제 연결은 CONNECT 403이었으나 2026-10-07 환경 재시작 후 실제 공개 일정/예상치 파싱이 성공했습니다. 실업수당 청구 예상 200K/이전 197K, 소비자심리 예상 47.5/이전 47.8을 확인했습니다. FOMC 등 없는 예상치는 미제공이며 이미 발표한 일정은 예정 목록에서 제외합니다. 환경 초안 게시와 실제 Streamlit 연결은 별개입니다. 기존 발표 조건부 가격 시나리오는 유지합니다.

`ImportError`가 `from btc_analyzer.candles import candle_boundary`에서 발생하면, 이전 버전의 Python 모듈이 서버 메모리에 남아 있는 경우를 확인합니다. 소스에 함수가 있어도 `sys.modules`의 이전 모듈에는 없을 수 있습니다. 현재 진입점은 프로젝트 코드의 내용과 로딩 경로를 확인하고 버전이 달라진 경우에만 자체 패키지·공개 계산 캐시를 갱신합니다. 같은 버전의 일반 새로고침에서는 모듈과 계산 캐시를 유지합니다. 계좌 DB나 개인 기록 파일을 삭제하지 않습니다.

오래된 모듈이 남은 업데이트 상황도 별도로 검사할 수 있습니다.

```bash
BTC_CHECK_STALE_IMPORTS=1 python -I scripts/check_deployment.py
```

이 검사는 이전 `candles` 모듈을 먼저 로딩한 상태에서 공개 앱을 실행하고, 최신 모듈로 복구된 뒤 반복 실행에서는 같은 모듈을 유지하는지 확인합니다. 이미 실패 중인 Community Cloud 앱은 수정 코드 반영 후 **Manage app → Reboot app**으로 기존 프로세스를 한 번 정리할 수 있습니다.

로컬과 공개 앱의 코인 분석은 Binance USDT Live입니다. 첫 화면은 BTC·ETH·SOL·XRP와 NQ·코스피의 시세 카드입니다. 상단은 공포·탐욕/환율/김프와 유가·미국 10년물/30년물 금리 요약이며, 종목 카드를 누르면 상세 차트·분석·예측을 엽니다. 코인 카드는 기존 ticker의 24시간 고가·저가·거래량·거래대금을 사용합니다. 자료가 없으면 —로 표시합니다. Upbit BTC는 김프 산출용으로만 수신합니다. Binance는 네 코인의 aggTrade+ticker를 한 연결에서 받고 REST 대체 조회도 네 심볼을 묶습니다. 공개 자료 조회에는 API 키가 필요하지 않습니다.

환율·NQ·WTI·10년물·30년물은 기존 iframe의 `wss://streamer.finance.yahoo.com/?version=2` 한 연결에서 `KRW=X`, `NQ=F`, `CL=F`, `^TNX`, `^TYX`를 구독합니다. 공개 PricingData base64/protobuf의 필요한 필드만 크기 제한 안에서 읽고, 틱은 Python 분석 없이 기존 FX/부모 네 카드에 반영합니다. 변경된 값/그래프만 그리며 부모 자동 갱신과 요소 교체 뒤에도 최신 스트림 값을 유지합니다. 서버의 `query1.finance.yahoo.com` chart v8(1분봉/1일)은 10초 공유 대체 조회입니다. REST `KRW=X`는 CURRENCY/KRW를 확인합니다. 스트림의 생략된 currency는 정확한 `KRW=X`/`CCY` 조합에서만 허용하고 명시된 다른 통화는 제외합니다. 3분 넘은 시장 환율은 새 김프 계산에서 제외합니다. 은행 고시/ECB 일별 대체값은 출처·시각을 구분합니다.

`NQ=F`는 NQ 선물, `CL=F`는 WTI 원유 선물(USD/배럴), `^TNX`/`^TYX`는 CBOE 10년물/30년물 수익률 지표(%)입니다. 현물 지수·Brent·CFD·국채 가격으로 대체하지 않으며 금리를 10으로 나누지 않습니다. 국채 변화는 %p로 표시합니다. 스트림 연결 여부와 원자료 시각/제공 지연은 별개입니다. NQ/WTI의 거래소 지연을 제거하려면 CME/NYMEX 실시간 이용 권한/제공업체 연결이 필요합니다. ^TNX/^TYX도 실제 국채 거래 가격 스트림이 아닙니다. 원자료가 오래됐거나 지연이 미확인이면 실시간으로 표시하지 않습니다. 프록시/지역/서비스 제한 시 대기/마지막 값과 재연결을 표시하며 가격을 만들어 넣지 않습니다.

뉴스는 서버에서 `news.google.com` 한국어·영어 RSS를 읽고 코인 연결과 시장 이벤트가 있는 최근 24시간 제목만 목록/전망에 사용합니다. 일반 유가·전쟁·주식 ETF와 매체 이름에만 코인이 있는 기사는 제외합니다. 자료원별 한 요청, 최대 4개 작업, 시세 10초·뉴스 30초 캐시, 연결/본문 제한과 오류 대기·Retry-After를 적용합니다. 시세 확인 2초, 뉴스 목록 10초 fragment로 분리해 코인 연결이나 봉 분석을 다시 실행하지 않습니다. 첫 코인 화면은 이 요청 완료를 기다리지 않습니다. 공개 자료에는 API 키나 새 운영 의존성이 필요하지 않습니다.

횡보 요약과 자주 움직인 시간의 카드/웹 시간대 집계를 제거했습니다. 보조 1시간봉은 720→260개로 줄여 지표 준비 이력을 유지합니다. 월별 히트맵은 이미 받은 월봉을 사용하므로 별도 요청이 없습니다. 급등락 감지는 기존 BTC/ETH 연결과 닫힌 분봉 이력을 유지하며 일반 흐름 카드/관련 뉴스만 표시합니다. 새 iframe/소켓/고정 터치 덮개를 추가하지 않습니다.

환율·김프에는 브라우저에서 `quotation-api-cdn.dunamu.com`(은행 고시), `api.frankfurter.dev`(일별 대체 환율), `api.exchange.coinbase.com`(USDT/USD)도 접근 가능해야 합니다. 인증키를 요구하지 않는 공개 조회이며 요청에 계좌 정보를 넣지 않습니다. 환율과 USDT/USD는 분 단위로 조회합니다. CORS·지역·서비스 제한으로 접근하지 못하면 숫자를 만들어 넣지 않고 대기/지연으로 표시합니다.

개발 클라우드의 기존 허용 목록은 Binance·Upbit만 포함했습니다. 새 세 자료원은 실제 요청에서 프록시 CONNECT 403이었고 필요한 도메인을 보존·추가한 환경 설정 **초안**을 저장했습니다. 환경 설정의 저장/적용 후 실제 요청을 다시 검사해야 하며, 이 초안이 Streamlit Community Cloud나 현재 프록시에 자동 적용된 것은 아닙니다. 응답을 주입한 브라우저 검사는 실제 외부 연결 성공과 구분합니다.

2026-10-06 최신 개발 확인에서는 Yahoo 다섯 종목 REST 파싱과 실제 WebSocket 연결/FX 메시지 수신이 성공했습니다. 이전 FX HTTP 429/CONNECT 403은 당시 기록이며 현재 모든 Yahoo 연결이 차단됐다고 단정하지 않습니다. 15초 재구독을 포함한 32초 관찰에서는 FX 메시지 8개만 수신했고 NQ/WTI/10년/30년물 스트림은 확인되지 않았습니다. 이전 날의 국채 값과 원자료 지연은 그대로 표시합니다. 공급자/무지연 권한은 설정되지 않았으며 공개 호스팅 재배포도 미확인입니다. 실제 코인 중심 한국어 RSS 요청/파싱 성공 기록은 유지합니다.

기존 Yahoo 도메인·설치·비밀 요구사항을 보존해 클라우드 환경 시작 지침 초안만 최신 구성/검증 결과로 갱신합니다. 환경 설정 초안은 검토/저장·게시 후 적용되며 Streamlit 배포를 수행하지 않습니다. 검사 fixture는 운영 데이터로 사용하지 않습니다.

## 기존 서버 또는 Docker

Python 호스팅에서는 저장소 루트에서 아래 두 명령을 사용합니다.

```bash
python -m pip install -r requirements.txt
sh scripts/start_web.sh
```

서버가 제공하는 `PORT`를 사용하며 기본값은 8501입니다. HTTPS 도메인과 WebSocket을 지원하는 서비스의 프록시를 연결해야 외부 접속이 가능합니다. XSRF/CORS 검증은 켠 상태로 유지합니다.

Docker를 지원하는 호스팅에서는 저장소의 `Dockerfile`을 사용합니다.

```bash
docker build -t btc-trading-analyzer:web .
docker run --rm -p 8501:8501 btc-trading-analyzer:web
```

컨테이너는 일반 사용자로 실행하며 healthcheck는 `/_stcore/health`를 확인합니다. Docker 실행만으로 HTTPS 도메인이 생기지는 않습니다. 호스팅 서비스에서 제공한 주소를 사용하세요.

관리자가 설정할 수 있는 선택적 환경 변수는 다음과 같습니다.

| 변수 | 기본값 / 용도 |
|---|---|
| `PORT` | `8501` · 호스팅 포트 |
| `BTC_WEB_DATA_DIR` | `data/web` · 쓰기 가능한 임시 데이터 루트 |
| `BTC_LOG_LEVEL` | `INFO` · 서버 로그 |

두 진입점 모두 개인 DB와 분리된 시장 캐시를 사용합니다. 로컬 실행은 `python -m streamlit run app.py`입니다. `BTC_DEFAULT_SOURCE`·`BTC_DEFAULT_EXCHANGE`는 웹 앱에서 더 이상 사용하지 않습니다. `BTC_DB_PATH`는 기존 CLI용이며 웹 화면의 시장 캐시 위치를 바꾸지 않습니다.

예정 경제 발표/시장 예상치에는 서버의 `nfs.faireconomy.media` HTTPS 접근이 추가로 필요합니다. 거래/API 키는 필요하지 않습니다. 이번 주 공개 캘린더를 30분마다 공유 조회하며 화면은 기다리지 않고 가격 분석을 계속 표시합니다. 오류/오래된 자료에는 실제 시각·예상치를 만들어 넣지 않고 발표 시나리오를 보류합니다. 2026-10-06 Codex 환경의 실제 요청은 프록시 거부였고 도메인을 기존 허용 목록에 더한 설정 초안을 저장했습니다. 초안 저장은 현재 실행 환경에 적용/게시하거나 Streamlit 재배포·자료 수신을 검증한 결과가 아닙니다. 설정 검토/저장·게시 후 실제 캘린더 수신을 확인해야 합니다. ## 네 코인 분석과 ETF 일별 수급

시세 카드와 상세 창의 자산 선택은 BTC/ETH/SOL/XRP/NQ/코스피입니다. 코인은 Binance USDT 쌍으로 공통 분석을 전환합니다. 네 시세의 aggTrade/ticker를 기존 `data-stream.binance.vision` 한 소켓에서 받고 선택 자산의 5m/15m/1h/4h/1d/1w/1M만 추가 구독합니다. REST 대체 ticker도 네 심볼 한 요청입니다. 시세 카드/최근 분봉은 별도로 갱신하며 서버 이력/예측을 틱마다 다시 계산하지 않습니다. 각 분석/브라우저 seed/가격 차트·예측에는 심볼을 전달해 전환 중 다른 코인 자료를 수락하지 않습니다.

ETF 서버 자료원은 `farside.co.uk/bitcoin-etf-flow-all-data/`와 `farside.co.uk/ethereum-etf-flow-all-data/`입니다. 기존 TLS/프록시를 유지하고 최대 2MB·한 피드에 한 진행 중 요청·10분 캐시/오류 대기와 마지막 발표를 사용합니다. 일별 Total 순유입(백만 USD), 날짜·펀드 열/총합 검사를 적용합니다. 음수 괄호·명시된 0·미제공 대시/빈칸을 구분하며 미발표일의 값을 만들지 않습니다. SOURCE 표의 ETH 날짜 제목은 빈 칸인 실제 형식을 허용하되 ETHA/IBIT 열을 검사해 자산을 분리합니다. 네이티브 카드/막대/펀드 표를 사용해 차트 SDK/iframe을 늘리지 않습니다.

**2026-10-15 KST 실제 HTTPS 200 및 BTC/ETH 각 최근 60개 원자료 파싱을 확인했습니다.** 당시 최신 거래일은 10월 14일, 총순유입 −150.5 / −19.7백만 USD였습니다. 이 수치는 해당 확인 시점의 자료이며 고정값으로 앱에 넣지 않습니다. 2026-10-17 SOL의 실제 자료원 `/sol/` HTTP 200과 분리된 BSOL 헤더/Total 표를 확인해 연결했습니다. XRP는 Farside 전용 자료가 없고 대체 후보 접속이 막혀 미연결로 표시합니다.

기존 custom 도메인/프리셋을 보존해 환경 초안에 `farside.co.uk`, `www.farside.co.uk`를 추가 저장했습니다. 현재 실제 접속 성공과 별도로, 다음 환경에 설정을 유지하려면 환경 설정에서 저장·게시합니다. 추가 패키지/API 키는 필요 없습니다. 공개 Streamlit 재배포/실사용자 연결은 별도 확인 대상입니다.


## NQ 분석·예상 지표·브라우저 자원

NQ 선택 시 별도 7봉 차트·추세 분석과 과거 유사 사례/1주·2주·1개월·2개월·3개월·6개월 전망을 제공합니다. Yahoo `query1.finance.yahoo.com`의 `NQ=F`/USD/뉴욕 시간대/요청 봉 주기를 검증합니다. 공개 시세는 지연될 수 있고 연속 선물 롤오버 차이를 포함합니다. 5분·15분·1시간봉은 CME 세션, 일봉은 자료원 발표 정규 거래일(단축장 제외) 기준이며 4시간·주·월은 이 자료를 합산합니다. 원자료 누락은 채우지 않고 해당 합산 봉을 보류합니다. Binance의 24시간 거래일·코인 뉴스/시세를 NQ 분석에 적용하지 않습니다. 선택한 시간대만 조회하며 60초 캐시와 실패 대기를 공유합니다. 거래 세션/DST 처리를 위해 `pandas-market-calendars`를 고정 의존성에 추가했습니다.

예상 EMA/볼린저는 실제 확정 이력의 지표 상태에서 선택한 예상 가격 경로를 이어 계산합니다. 경로 조건의 지표이며 추가적인 정확도나 가격 불확실성 범위로 설명하지 않습니다. 코인은 기존 현재가 재계산 한 번에 예상 지표도 묶어 갱신합니다.

긴 브라우저 코드는 `src/btc_analyzer/ui/browser/`의 JS/CSS/HTML로 나누고 `browser_assets.py`가 캐시해 기존 iframe 하나로 합칩니다. 설치 패키지에도 이 자원을 포함합니다. Cloud의 오래된 모듈 복구 해시는 Python뿐 아니라 이 자원 변경도 확인합니다. UI는 시장 개요/미래 예측 두 탭이며 삭제한 기술 지표/다중 시간대/횡보 요약은 다시 실행하지 않습니다.

XRP 후보 `sosovalue.com`, `api.coinmarketcap.com`, `www.coinglass.com`을 기존 네트워크 목록을 보존해 환경 설정 **초안**에 추가했습니다. 초안은 현재 환경 적용/게시가 아닙니다. 접속이 계속 차단돼 실제 응답 형식과 신뢰도를 확인하지 못했으므로 파서나 ETF 숫자를 추측하지 않았습니다. 환경 설정 적용 후 확인 가능한 XRP 자료원 연결이 남아 있습니다. Streamlit 호스팅의 네트워크는 이 클라우드 환경과 별개입니다.

## OpenAI 가격 분석

앱 운영자가 Streamlit의 **Manage app → Settings → Secrets**에 아래 이름으로 키를 등록합니다. `발급받은 키` 부분은 설정 화면에서만 입력하고 저장소에 커밋하지 마세요.

```toml
BTC_AI_API_KEY = "발급받은 키"
BTC_AI_MODEL = "gpt-4.1-mini"
```

기존 호스팅의 `OPENAI_API_KEY`도 지원하며 `BTC_AI_API_KEY`가 우선합니다. 로컬/클라우드 프로세스는 환경 변수로 같은 이름을 받습니다. 이 개발 환경의 예약된 `OPENAI_` 변수 대신 `BTC_AI_API_KEY` 비밀 요구를 등록했습니다. 환경 설정 초안에는 기존 22개 custom hosts를 보존한 `api.openai.com` 추가(총23개), 키 요구, 모델 변수까지 저장했습니다. **초안 저장은 현재 환경 적용/게시가 아닙니다. 환경 설정에서 검토·저장하고 게시해야 이후 환경에 적용됩니다.** Streamlit Secrets와 호스팅의 접속 설정은 별개입니다.

서버의 고정 HTTPS Responses API만 사용하고 리디렉션/브라우저 키 전송은 허용하지 않습니다. 공식 JSON Schema 응답과 가격 단위·범위·제공된 근거 ID를 검증합니다. 제목은 미검증 데이터로 전달하며 도구/웹 탐색은 사용하지 않습니다. 현재 자료에 없는 미래 뉴스·발표 결과를 알고 있다고 표시하지 않습니다. AI 경로는 보고서의 가격 중심/범위를 기존 모델 경로로 연결한 조건부 시나리오입니다. 검증 모델과 가중 비중은 그대로 유지합니다.

**AI로 가격대 분석** 버튼으로만 요청합니다. 한 작업자·진행/대기 최대2건·결과 최대24개·15분 캐시·오류30초 대기를 사용하며 차트 조작은 API를 호출하지 않습니다. 연결/읽기 시간 제한과 본문 크기 제한을 적용합니다. 실제 API 요금은 등록한 키의 계정에 발생합니다. 공개 앱 방문자의 버튼 요청도 운영자 키를 사용하므로 공유 범위와 OpenAI 프로젝트 지출 한도를 설정하세요.

2026-10-18 KST 개발 검증은 제공자 응답을 재현한 프로토콜/브라우저 검사입니다. 실제 키는 미등록이고 현재 환경에서 OpenAI 접속은 ProxyError여서 **실제 유료 모델 호출 성공은 미확인**입니다. 키/접속 설정 적용 후 선택 자산·기간의 실제 카드/모델·기준 시각, 가격 범위/근거/그래프를 확인하는 단계가 남아 있습니다. 공개 Streamlit 재배포·실사용 Safari도 별도 확인 대상입니다.

## 초기 수집·차트 이동 경량화

초기 OHLCV는 기존 CCXT의 공식 public klines를 바로 호출해 exchangeInfo 전체 목록 로딩을 생략합니다. 정상TLS·환경프록시·요청 제한/오류 처리·페이지 전진·확정 봉/누락 검사는 유지하며 새 도메인/키/운영 패키지는 없습니다. 시세 iframe을 보낸 다음 필요한 DataService를 불러옵니다.

`chart-preview.js`는 기존 SVG 가격/지표/거래량을 RAF로 변환합니다. 이동 중에는 전체 Plotly 축 재계산을 하지 않고 손을 놓으면 원래 스타일을 돌리고 축/오토를 반영합니다. 취소는 임시 이동을 버리며 연속 손가락 변경은 마지막 표시 위치를 잇습니다. 정확한 축 반영이 끝날 때까지 해당 plot의 실시간 갱신을 보류하고 다른 시세는 계속 받습니다. 새 JS는 기존 iframe 안에 합치며 패키징/체크아웃 세대 해시에 포함합니다. Service worker에 시세/예측을 저장하지 않습니다.

`benchmark_chart_gestures.py --app-url <개발 fixture> --cpu 4 --repeats 2`로 실제 브라우저 재배치 횟수·프레임 간격을 기록하고, `check_chart_preview.py`로 캔들의 실제 이동 거리·종료/취소·한손/두손 연속과 추가 Python0을 검사합니다. 실제 시장/물리기기나 호스팅의 휴면 후 기동 시간을 이 측정에 포함하지 않습니다.


## 카드형 시세 목록과 상세 화면

`?market=BTC&view=chart`처럼 유효한 시장 코드를 지정하면 해당 상세 창을 바로 엽니다. 목록의 카드와 상세의 현재가는 같은 브라우저 연결을 사용합니다. 작은 화면은 두 열 카드/전체 화면 상세, 태블릿은 두 열 카드, 큰 화면은 네 열 카드로 정리합니다. 360px 미만에서는 한 열을 사용합니다. 상세 창 안에서 세로 스크롤하고 ×로 목록으로 돌아옵니다. 별도의 계정·로그인·주문 기능은 추가하지 않습니다.

개발 브라우저 검사는 기존 서버 URL의 `?market=BTC&view=chart` 주소로 분석을 엽니다. `check_market_board.py --app-url <서버 루트> --event-log <계측 로그>`는 목록의 이력 호출0/6카드 상세·터치·스크롤·공유 연결을 검증합니다. 설치 검사는 루트 목록에서 시작하고 오프라인 복귀 뒤 카드를 열어 확인합니다. fixture 결과와 실제 공개 배포/물리 Safari 확인은 구분합니다.
